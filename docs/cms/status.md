**What works today:** open `localhost:4321/admin/` in Chromium → "Work with Local Repository" → pick repo root → edit any of 55 EN pages with a structured form per section type. Saves write to local files via the File System Access API; commit manually.

**What we validated in S2 smoke-test:**
- Round-trip preserves all section data on a complex page (homepage with 13 typed sections).
- Cosmetic YAML normalization on save: quotes stripped, blank lines removed, block scalars `|` → `|-` / flow.
- No "field not defined" warnings clicking through pages with the full schema loaded.

**What we did NOT validate:**
- A save round-trip through the *full* S2 schema (the earlier test was through S1's minimal `body`-only config, which let unmapped `sections:` pass through). See Phase A below.

**Known minor concerns going in:**
- Empty optional fields materialize on save (e.g. `cover: ''` was injected when the source didn't have it).
- `feature-row.cta` was conditional in Keystatic; modeled as plain optional object — may serialize as `cta: {}` when unset.
- n8n writes quoted strings; Sveltia strips them. Two-way churn in git history but no correctness impact.
- Sveltia's built-in AI translation is cloud-only (OpenAI Responses API hardcoded) — local LLM only viable via n8n routed at Ollama, not via the Sveltia "translate" button.

## Phase A — Finish validating S2 ✅ DONE 2026-05-04

Saved homepage description through Sveltia, inspected diff, build passed, no visual regressions. Reverted test edit.

**Findings:**
- `feature-row.cta` does NOT materialize as `cta: {}` when unset — risk dodged.
- `compareBefore`/`compareAfter` preserve their values cleanly when present (homepage's fast-implementation block round-tripped fine).
- `cover: ''` IS injected at page level on save when source omits it. Tolerable.
- **New finding:** Sveltia reorders fields within a section to match the schema's field order, not the source's. e.g. `headline` moves above `zone` on first save. One-time churn per section per page, no semantic impact (Zod doesn't care about field order).
- Cosmetic churn confirmed on full schema: quote stripping, `|` → `|-`, inline-flow `{ k: v }` → block-style mappings, blank-line removal between sections.

## Phase B — S5 — n8n coexistence guardrails — ~45 min

The actual operational risk once editing starts: editor + n8n racing on the same files.

**Steps:**
1. Document write-ownership in `astro-reveal/n8n-contract.md`:
   - Editor (Sveltia) → `src/content/pages/en/*`, `src/content/i18n/en.yml` only.
   - n8n → `src/content/pages/{es,ja,ko,pt-BR}/*`, `src/content/i18n/{es,ja,ko,pt-BR}.yml` only.
2. Add a pre-commit / CI guard script: fails if a single commit touches both `en/` and a non-en locale.
3. (Once Phase D adds non-EN collections) drop a `description:` banner at the top of each: "Auto-generated by n8n. Edit /en instead — changes here will be overwritten."

**Exit criteria:** the contract is documented and a guard exists that catches accidental cross-locale commits.

## Phase C — Sveltia i18n config — ~30 min

Sveltia currently doesn't know this is a multilingual site. Adding the `i18n` block:

- Top-level: `i18n: { structure: multiple_folders, locales: [en, es, ja, ko, pt-BR], default_locale: en }`.
- Per-field flags inside the 27 section types:
  - `i18n: translate` for human-readable text (headlines, body, CTA labels, FAQ Q&A).
  - `i18n: duplicate` for non-translatable values (URLs, image paths, CSS classes, `zone`, `variant`, anchor IDs, srcset entries).
  - No flag for fields that Sveltia should treat as fully per-locale.

**Doesn't change behavior today** — but enables Phase D to work cleanly and is required before any future "translate via Sveltia" experiment.

**Exit criteria:** config.yml builds, admin still loads, no warnings.

## Phase D — Non-EN read-only collections ✅ DONE 2026-05-05

Commit `d40bb03`. Added `pages_es`, `pages_ja`, `pages_ko`, `pages_pt_br` to `config.yml`, each with `create: false` / `delete: false` and a `description:` banner. Field schema reused from `pages_en` via YAML anchor (`&pages_fields` → `*pages_fields`) — single source of truth, no copy-paste drift.

**Verified:** all five collections load in Sveltia admin. JA homepage (11 typed sections) and JA about-us (body-only) render the structured form with no "field not defined" warnings. The `ctaHref` leak from `ja_localization_pending.md` did not materialize at the page-frontmatter level — it only affects `SectionRenderer` runtime output, not source files, so the schema didn't need to absorb it.

**Phase C was skipped:** read-only collections don't need per-field `i18n: translate` / `i18n: duplicate` flags. Revisit only if someone ever wants to use Sveltia's built-in translate button.
