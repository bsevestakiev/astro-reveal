## 1. Footer wave white-strip

**Files:** `astro-reveal/src/components/ui/Footer.astro`, `astro-reveal/src/pages/index.astro`

**Problem:** Visible horizontal white strip between the last page section and the footer gradient. Earlier attempt used a gradient-fill SVG; user rejected it. Required exact replication of the original WP wave.

**Diagnosis:**
- The original `www.revealbi.io/index.html` uses an SVG with white-fill path (`fill:#fff;stroke:#fff`) inside a `<section class="bg-gradient--primary">`. The illusion works when the page section above is pure white — the SVG's white-fill area blends seamlessly and the wave curve is the only visible boundary.
- `pricing.html` of the original site has a JS snippet that dynamically sets the wave fill color to match the section above (buggy — queries the first section, then hardcodes `#f8f9fa`). Confirmed the wave is meant to color-match the section above per page.
- **Root cause of the visible strip in our build:** decorative pink radial-gradient circle in homepage Zone 3 (`circle-loved-users-pink` at `top:85%; left:-20%`, 600px) was bleeding into the InlineCTA's bottom area. The page bg there became faintly pink-tinted; the wave SVG's pure `#fff` fill contrasted with it, producing a sharp horizontal seam.

**Fix (commit `ae6dba9`):**
- Replaced the gradient-fill wave with the original WP markup byte-for-byte: `version="1.1"`, `viewbox` (lowercase), `enable-background`, `xml:space="preserve"`, `class="ie-hide"`, `style="fill:#fff;stroke:#fff"` on the path.
- Added `display:block;` to the SVG style and collapsed whitespace between the `<section>` opening tag and the `<svg>` to eliminate inline-element baseline gap.
- Added inline `<script is:inline>` that samples the actual painted pixel above the wave via `document.elementFromPoint`, walks the parent chain for the first non-transparent `background-color`, and applies it to the path's `fill` + `stroke`. Works on every page — not just homepage.
- Removed the bottom-most decorative circle in Zone 3 of `index.astro` (the one at `top:85%`). The remaining 3 circles stay in the upper half of Zone 3, well above the InlineCTA.

**Status: FIXED**

## 2. Sticky navigation broken

**Files:** `astro-reveal/public/js/maxmegamenu-pro.js` (new), `astro-reveal/src/layouts/BaseLayout.astro`

**Problem:** Header's `data-sticky-*` attributes had no effect — nav scrolled away with the page.

**Diagnosis:** The sticky feature is a **Pro** plugin feature, implemented in `wp-content/plugins/megamenu-pro/assets/public.js`. The free `maxmegamenu.js` (already in our build) has zero sticky logic. The Pro JS was never copied during migration.

**Fix (commit `b5d02d3`):**
- Copied `maxmegamenu-pro/assets/public.js@ver=2.3.1.1` to `astro-reveal/public/js/maxmegamenu-pro.js`.
- Added `<script is:inline src="/js/maxmegamenu-pro.js"></script>` to `BaseLayout.astro` directly after the free maxmegamenu.js.
- The Pro JS reads the `data-sticky-*` attributes already present on `#mega-menu-max_mega_menu_1` and toggles the `.mega-stuck` class on scroll. The `.mega-stuck` styling is already in `vendor/megamenu.css`.

**Status: FIXED**

## 3. Missing gray "Request a Demo" bar in dropdowns

**Files:** `astro-reveal/src/styles/styles.css`, `astro-reveal/src/components/ui/Header.astro`

**Problem:** Original site has a light-gray bar containing "Request a Demo" at the bottom of each Product / Solutions / Resources dropdown panel. Our build lacked it.

**Diagnosis:**
- The original markup has each megamenu dropdown structured as `row0` (link grid) + `row1` (full-width "Request a Demo" bar). The gray bg on `row1` isn't from a class in the static CSS we have — but it's clearly present visually on the live site.
- Our Product/Solutions dropdowns had the row0/row1 structure already. **Resources had only `row0` with Request a Demo embedded as the 4th column** instead of as a separate bottom row.

**Fix (commit `b5d02d3`):**
- Appended a CSS rule to `styles.css` (desktop-only ≥1201px) targeting the last `.mega-menu-row` inside `li.mega-menu-megamenu > ul.mega-sub-menu`, applying `background: #f4f5fd` (matches the brand's existing light-gray-blue tint).
- Restructured the Resources dropdown in `Header.astro`: pulled "Request a Demo" out of column 4 of `row0` and into a new `row1` matching Product/Solutions, so the `:last-child` selector applies consistently across all three dropdowns.

**Status: FIXED**
