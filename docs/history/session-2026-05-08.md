## Comparison-table block — `<reveal-expandable-table>`

Replaces a recurring WP gutenberg pattern: a swipeable comparison table with a click-to-fullscreen affordance. The original WP version inlined ~120 lines of CSS + a `<script>` block into post markdown — five blog posts had the cruft inline and another ~five were stripped during port losing the expand behavior.

Built as a **progressive-enhancement custom element**, not a section component, because blog posts are body-rendered (not section-dispatched). The same tag works in any markdown body site-wide.

### Files

| File | Role |
|---|---|
| `public/js/reveal-expandable-table.js` (new) | Custom element class. Wraps the child `<table>`, injects styles once on first connection, adds expand button + ESC/click-to-close fullscreen state. |
| `src/layouts/BaseLayout.astro:198` | One-line script tag. Loads sitewide with `defer`; bails harmlessly on pages without the element. |

### Authoring shape

```html
<reveal-expandable-table>

| Old approach | New approach |
| --- | --- |
| ... | ... |

</reveal-expandable-table>
```

The blank lines around the table are required so Astro's markdown renderer still parses the table.

### Posts that already use it
- `ai-powered-analytics.md`
- `ai-token-cost.md`
- `legacy-vs-modern-embedded-analytics.md`
- `white-label-analytics.md`
- `white-label-analytics-platform.md`

The cleanup script in this session auto-wraps the dominant comparison table for these slugs when mirroring from WP. Future posts authored manually can use the tag directly.

## Sveltia toolbar button — "Comparison Table"

So marketing editors don't have to type the wrapper tag.

### Files

| File | Role |
|---|---|
| `public/admin/editor-components.js` (new) | Registers the button via `CMS.registerEditorComponent(...)` — Sveltia inherits Decap's API. Form has a header-row string field + a list of row strings, all pipe-separated. Round-trips via the `pattern` regex so existing blocks parse back into the form. |
| `public/admin/index.html` | One added `<script>` line loading editor-components.js after Sveltia. |

### Surfaces where the button appears
Any `widget: markdown` field in `public/admin/config.yml` — registration is global. Currently that's `pages_en` body. When `blog_en` collection gets added (deferred CMS S2/S3, see `docs/cms/status.md`), the button surfaces there automatically with no extra work.

### Adding more components later
Pattern is in `editor-components.js`. Each new block needs: `id`, `label`, `fields[]`, `pattern` regex, `fromBlock`, `toBlock`, `toPreview`. Wrap the `CMS.registerEditorComponent(...)` call in the existing IIFE.

## Content sync — 16 high-drift blog posts mirrored from WP

The content-similarity audit revealed Astro had drifted significantly from WP for posts that marketing edited recently. Two of the worst offenders (`white-label-analytics`, `white-label-analytics-platform`) were modified on WP just 3 days before the export and were essentially rewritten.

### Method
Script at `/tmp/mirror-from-wp.py` (not committed) read each WP-export body, applied a cleanup pass, and pasted the result into the Astro file while preserving Astro frontmatter wholesale. Cleanup pass:
- Drop CSS-in-prose blobs (the expand-table widget pattern) and widget `<script>` blocks
- Remove empty `<div></div>` separators
- Expand `[cta_banner type='X' headline='Y' msg='Z' button_text='B' button_link='/L']` → 3-line plaintext (matching the existing port style)
- Expand `[custom_pdf text='X' link='Y']` → `[Download the PDF](Y) — X`
- Rewrite `assets/images/foo.png` → `/images/<year>/<month>/foo.png` by resolving against `public/images/`
- Wrap the dominant comparison table in `<reveal-expandable-table>` for the 5 widget-using posts

### Posts mirrored (16)
white-label-analytics, ai-token-cost, legacy-vs-modern-embedded-analytics, reveal-1-4-0-release, erp-and-embedded-analytics, ai-powered-analytics, embedding-self-service-bi-in-react-apps-with-node-js, embedding-bi-in-blazor-applications, analytics-sdk, slm-vs-llm, white-label-analytics-platform, mobile-business-intelligence-bi, embedding-bi-in-angular-apps, reveal-ai-release, reveal-data-driven-decision-making.

### Two regressions caught and fixed mid-session

1. **Internal-link rewrites lost (~150 links).** WP source has absolute `https://www.revealbi.io/foo` URLs; the Astro ports had rewritten these to internal `/foo`. Mirror reverted them. Fixed with a regex pass restricted to markdown link parens (`](...)` only, not bare prose mentions).
2. **Form blocks lost (3 tutorial posts).** `embedding-bi-in-angular-apps`, `embedding-bi-in-blazor-applications`, `embedding-self-service-bi-in-react-apps-with-node-js` had inlined HTML lead-capture forms (≈1.5 KB each: labels, reCAPTCHA disclaimer, success state). WP renders these via `[custom_pdf]` shortcode → server template, so the export only has the shortcode. Restored each form block from `git HEAD` by replacing the expanded `[Download the PDF]` line with the original ~50-line form markdown.

### Final parity verdict
12/15 paragraph-perfect against WP. The 3 form-restored tutorial posts have 1 expected WP-only paragraph (the shortcode that got swapped) + the form chrome as Astro-side additions — by design.

### What was deliberately NOT mirrored

The remaining 89 posts:
- ~52 are already content-identical (≥0.95 similarity) — only smart-quote / em-dash / whitespace differences. Mirror = no-op.
- ~37 have minor edits where Astro carries deliberate improvements (internal-link rewrites, expanded `[cta_banner]` shortcodes, inlined form HTML where applicable). Mirror would re-introduce the regressions we just cleaned up.

User intent confirmed mid-session: "keep what we built in Astro, just sync the content." The 16 = real content drift; the 89 = formatting differences or intentional Astro additions.
