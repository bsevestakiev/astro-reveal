## Tracking/analytics wiring — Phases 1–3 done

Plan at `/mnt/c/reveal/tracking-next.md`. Original budget ~3h; actual ~2h.

### Phase 1 — `robots.txt` templatized off `PUBLIC_SITE_URL`

**Commit:** `5d7907b`

Replaced static `public/robots.txt` (hardcoded `www.revealbi.io`) with `src/pages/robots.txt.ts` that reads `Astro.site`. Sitemap line now stays in sync with whatever host the build is targeting. Same env var the sitemap-index already uses.

### Phase 2 — `leadTracker.js` respects `PUBLIC_LEAD_API_BASE`

**Commits:** `9c8e5bf` (initial), `a36eba5` (fix)

Added `_apiBase()` helper that reads `window.__REVEAL_CONFIG__.leadApiBase` (env-injected) and falls back to the legacy hostname-based auto-routing (staging URL → staging.infragistics.com, prod URL → www.infragistics.com) when empty. Three callsites swapped: lead-tracking POST, product-resource POST, product-resource GET.

**Caught a bug in my own first commit:** `env.ts` had a default of `acctapis.infragistics.com` for `LEAD_API_BASE`, which meant the runtime config was never empty and the fallback never fired. Fixed in `a36eba5` by clearing the default. Now empty stays empty, fallback works. Saved memory `lead_api_host_unresolved.md` flagging the unresolved `acctapis` vs `www.infragistics.com` question.

### Phase 3 — Lead-form wiring + env-gated reCAPTCHA v3

**Commit:** `1d9a329`

Scope was bigger than the original plan suggested. Found that `leadTracker.execute({...})` was never called anywhere in the codebase, so **all 6 lead forms across the site were dead** (not just missing reCAPTCHA). Mirrored WordPress's per-form settings templates and wired each form via inline init scripts:

| Form | Component | Settings |
|---|---|---|
| Industry-page demo request (18 pages) | `LeadCaptureForm.astro` | tier_1 / A800001 / "demo request" |
| Footer newsletter (every page) | `Footer.astro` | tier_2 / A800003 / "newsletter signup" |
| Header demo modal (every page) | `DemoModal.astro` | tier_1 / A800001 / formContainerId="modal-demo_0000" |
| Pricing-page quote | `PricingHero.astro` | tier_1 / A800005 / "pricing quote" |
| Whitepaper download | `WhitepaperLayout.astro` | tier_1 / A800001 / "demo request" |
| Request-demo body form | `request-demo.md` (markdown body) | tier_1 / A800001 / "demo request" |

reCAPTCHA: `Analytics.astro` injects the `<script>` only when `PUBLIC_RECAPTCHA_SITE_KEY` is set. `leadTracker.js` was patched to guard the `grecaptcha.execute` call so forms still submit (without a token) when reCAPTCHA isn't loaded. Site key flows from env → `__REVEAL_CONFIG__.recaptchaSiteKey` → each form's `reaptchaKey` setting at runtime.

**Caveat:** the `<script>` block in `request-demo.md` body sits in markdown content. n8n's translation pipeline may process it — needs verification after the next non-EN re-translation. Workaround if strings get translated: convert request-demo to use the `LeadCaptureForm` section type instead of body HTML.
